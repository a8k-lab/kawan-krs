# KawanKRS web

React + TypeScript SPA built with Vite, Tailwind CSS, and TanStack Router.

## Commands

Run from the repository root:

```bash
pnpm --filter web dev             # Vite; /api proxies to localhost:3001
pnpm --filter web routes:generate # Regenerate the typed route tree
pnpm --filter web typecheck       # Generate routes, then check TypeScript
pnpm --filter web test            # Routing and existing-behavior regression tests
pnpm --filter web build           # Generate routes, typecheck, production build
pnpm --filter web preview         # Preview the production SPA
```

## Organization

```text
src/
  app/           # Application bootstrap, router factory, routing tests
  routes/        # Thin file-based route definitions and page titles
  features/
    auth/        # Existing login/register forms and API calls
    mahasiswa/   # Shared layout, in-memory state, recommendation/history pages
    dosen/       # Shared state, student list/detail pages
    admin/       # Shared layout/state and administrative pages
    superadmin/  # Shared layout/state and administrative pages
  components/    # Cross-feature components, including the demo switcher
  lib/           # Shared frontend utilities; @/* resolves into src/*
  routeTree.gen.ts # Generated by TanStack Router; do not edit manually
```

The Vite router plugin runs before React and automatically generates routes and
splits route components into chunks. The CLI also generates the tree before
standalone typechecks and tests. Commit the generated tree with route changes;
linting/formatting already exclude it. Keep reusable feature code outside `routes/`.

## URLs

- `/login`, `/register`
- `/mahasiswa/rekomendasi`, `/mahasiswa/riwayat`
- `/dosen/mahasiswa`, `/dosen/mahasiswa/$mahasiswaId`
- `/admin`, `/admin/mata-kuliah`, `/admin/biaya`, `/admin/pengguna`
- `/superadmin`, `/superadmin/pengguna`, `/superadmin/audit`

`/` redirects to `/login`; `/mahasiswa` and `/dosen` redirect to their first page.
Unknown routes show a 404 with a link back to login. Navigation uses typed router
links; browser back/forward and direct URLs select the corresponding page.

Role layouts own feature state through React context so switching between nested
pages retains edited inputs, filters, and demo data. Leaving that role or refreshing
resets this state. Filters and expanded panels remain local rather than URL state.

## Authentication boundary

This migration intentionally preserves the existing prototype behavior:

- Login/register still call their existing `/api/auth/*` endpoints.
- Login still stores session data in localStorage and redirects by the returned role.
- Logout still navigates to login; it does not revoke or clear a session.
- The demo role switcher stays available; dashboards have **no route guards**.
- Lecturer detail URLs carry a student ID, but the existing detail UI remains a
  static demo and does not fetch student-specific records.

These routes are not an authorization boundary. Real session validation, backend
permissions, secure registration, and production removal of demo access remain
required before release (see ADR-0002 and ADR-0003). Query/Form migration is outside
this routing change.

## Deployment

Deploy the output in `apps/web/dist`. The host must fall back to `index.html` for
SPA routes so refreshes and deep links work. The root `netlify.toml` already defines
this fallback; retain it when deploying elsewhere.
